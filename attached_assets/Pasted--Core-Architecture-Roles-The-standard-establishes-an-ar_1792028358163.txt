
Core Architecture & Roles

The standard establishes an architectural layout divided into three foundational components:
• MCP Host: The main operating application where the LLM is embedded or runs (e.g., Claude Desktop, Cursor IDE, or AutoGen).
• MCP Client: The module within the host application that translates LLM requests and answers, handles discovery, and handles protocol negotiations with servers.
• MCP Server: Lightweight microservices or standalone code wrappers that expose context, data, and active capabilities from specific backend tools (such as Postgres databases, Slack, Google Calendar, or local file systems).

The Three Pillars of MCP Capabilities

The protocol relies on a JSON-RPC 2.0 communication format across local stdio streams or remote web transports (like HTTP and Server-Sent Events). It standardizes how servers expose information to a model via three capabilities:
• Resources: Declarative, read-only data sources. This allows an AI model to safely browse raw file directories, fetch live server metrics, or read continuous business documentation as structured text.
• Tools: Executable functions that the AI can explicitly choose to invoke. Tools let the AI perform real-world modifications like writing a new file, issuing an API call, running a terminal script, or deploying cloud infrastructure.
• Prompts: Pre-designed, contextual prompt templates. Servers can feed structured guidelines or workflow shortcuts straight into the model's reasoning loop to optimize how it tackles specific tasks.

The Evolution: The "Stateless" Shift

The architecture has transitioned into an enterprise-ready system via the MCP 2026-07-28 Specification.
• Stateless by Design: Early iterations required stateful, sticky connections—which grew incredibly complex when scaling to remote web systems. The modern specification rewrote the core SDKs to make MCP entirely stateless at the protocol layer, leveraging multi-round-trip requests and standardized HTTP headers.
• Built-in Asynchronous Tasks: Simplifies long-running operational queues with standardized polling, mid-flight input prompts, and durable workflow handles.
• Inline App Windows: Formalized a feature known as "MCP Apps," which allows servers to deliver interactive web UI fragments (like charts, visual data graphs, or interactive forms) directly inside an AI conversation window.

Security, Trust & Enterprise Governance

Because MCP grants AI systems the potential to execute code and query private data silos, security standards are highly regulated:
• Identity Framework: The specification elevates OAuth 2.1 with Proof Key for Code Exchange (PKCE) to a first-class citizen. This connects user permissions straight to enterprise identity providers.
• Authorization Tightening: For remote servers, the protocol relies on strict pre-registered clients and Client ID Metadata Documents (CIMD) to combat spoofing. Dynamic Client Registration (DCR) has been deprecated to narrow malicious entry points.
